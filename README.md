# Palette Forge

이미지와 영상을 제한된 팔레트 및 픽셀 스타일로 변환하는 브라우저 기반 도구입니다. 이미지에서는 고정 RGB 색상, 색상별 가중치, 자동 팔레트 성향, 경계 인식 면 정리와 일괄 내보내기를 제공하고, 영상에서는 전체 공통 팔레트와 장면 변화에 반응하는 프레임별 자동 팔레트를 지원합니다. 원본 미디어와 설정은 서버로 전송하지 않으며 현재 브라우저 메모리에서만 처리됩니다.

## 실행

Node.js 22 이상과 pnpm이 필요합니다.

```bash
pnpm install
pnpm dev
```

터미널에 표시되는 주소(기본값 `http://localhost:3000`)를 브라우저에서 엽니다.

배포용 빌드:

```bash
pnpm build
pnpm start
```

## 사용 순서

1. PNG, JPEG 또는 WebP 이미지 한 장 이상을 불러옵니다.
2. 목록에서 편집할 이미지를 선택하고 밝기·대비·채도·색조를 슬라이더 또는 숫자 입력으로 조절한 뒤 선택적 픽셀화를 설정합니다. 원본 미리보기 우하단의 `원본 / 보정` 버튼으로 처리 전후를 전환하며 확인할 수 있고, 맞춤 버튼은 이미지 전체 보기와 실제 100% 크기를 전환합니다.
3. 최종 색상 수(1~32)를 정합니다.
4. 팔레트 슬롯을 눌러 HEX/RGB 또는 색상 선택기로 고정 색상을 지정합니다. 이미지 내부 스포이드는 슬롯 선택 후 사용할 수 있습니다.
5. 필요하면 슬롯별 가중치(0.1~5)를 바꾸고 **변환 실행**을 누릅니다.
6. 설정 저장 창에서 ADJUST와 PALETTE 중 하나 또는 둘 다 선택해 JSON으로 저장하거나, PNG/JPEG/WebP로 현재 이미지 또는 전체 이미지를 내보냅니다.

설정은 이미지별로 독립적으로 유지됩니다. 설정 JSON을 불러오면 현재 선택된 이미지에만 적용됩니다.

## 영상 변환

상단의 **영상 변환** 버튼에서 MP4 또는 WebM 영상 한 개를 불러올 수 있습니다. 영상 설정은 창을 열 때 현재 선택된 이미지의 색 보정·픽셀화·팔레트 값을 복사하며, 영상 창 안에서 별도로 수정할 수 있습니다.

- **전체 영상 공통 팔레트**는 영상 전 구간에서 최대 24개의 프레임을 균등하게 분석하고 하나의 팔레트를 만든 뒤 모든 프레임에 사용합니다. 색상 깜빡임이 적어 기본값입니다.
- **프레임별 자동 팔레트**는 각 프레임에서 팔레트를 다시 생성하면서 OKLab 슬롯 매칭, 장면 전환 감지, 적응형 시간 보간과 픽셀 경계 히스테리시스로 색상 깜빡임을 줄입니다. 공통 팔레트보다 장면별 색을 잘 반영하지만 빠른 움직임이나 복잡한 그라디언트에서는 일부 변화가 남을 수 있습니다.
- 분석 0~20%, 프레임 변환 20~98%, 파일 마무리 99%, 완료 100%로 진행률을 표시하며 처리 중 취소할 수 있습니다.
- MP4는 H.264, WebM은 VP9으로 다시 인코딩합니다. 입력과 같은 컨테이너를 유지하고 호환되는 원본 오디오 트랙은 디코딩·재압축하지 않고 그대로 복사합니다.
- 투명 WebM은 알파 채널을 유지합니다. H.264가 요구하는 짝수 해상도를 맞추기 위해 홀수 크기의 MP4 입력은 가로 또는 세로가 최대 1px 커질 수 있습니다.
- 영상과 결과는 서버로 전송하지 않습니다. 디코딩·팔레트 계산·인코딩은 WebCodecs와 Mediabunny를 사용해 브라우저에서 처리합니다.
## 이미지 처리 방식

처리 순서는 항상 다음과 같습니다.

```text
원본 이미지 → 밝기/대비/채도/색조 보정 → 선택적 픽셀화 → 팔레트 생성 → 팔레트 색상으로 매핑
```

- 팔레트 생성은 OKLab 공간의 결정론적 k-means를 사용합니다.
- 고정 슬롯은 변경되지 않는 중심으로 유지하고, 나머지 중심만 이미지에서 계산합니다.
- 자동 중심 초기화는 고정 색상과 이미 선택된 중심에서 가장 먼 표본을 순서대로 고르는 방식이라 실행마다 결과가 같습니다.
- 투명도가 0인 픽셀은 팔레트 생성과 고유 RGB 색상 수에서 제외합니다. 나머지 픽셀의 알파 값은 유지합니다.
- 픽셀화는 기본적으로 꺼져 있으며 2~64px 블록 크기를 지원합니다. 투명 이미지는 부분 투명도를 유지하는 `부드러운 알파`와 블록 평균 알파 50%를 기준으로 완전 투명/불투명만 사용하는 `0 · 1 알파` 중에서 선택할 수 있습니다.
- 픽셀화 결과는 원본 해상도로 저장하거나, 블록 하나를 출력 픽셀 하나로 만드는 픽셀 최적화 해상도(`ceil(가로/블록 크기) × ceil(세로/블록 크기)`)로 내보낼 수 있습니다.
- 자동 팔레트 성향은 화면에서 `-50`(주조색 우선)부터 `0`(기본 원본 균형), `+50`(색상 다양성)으로 표시되며 슬라이더와 숫자 입력을 함께 지원합니다. 기본 `원본 균형`에서는 주조색을 유지하면서 충분한 면적의 적·청·황 등 강조색을 별도 후보로 보존합니다. 극소수 픽셀이나 거의 투명한 색은 강조색 후보에서 제외합니다.
- 팔레트 프리셋 창에서 게임보이, 회색조, 대지, 바다, 노을, 프리즘 팝, 코스믹 캔디, 호박빛 먹선, 사이버 네온, 레트로 아케이드 팔레트를 미리 보고 선택할 수 있습니다. 선택한 색은 `색 고정`으로 적용되고 가중치는 이미지에 맞춰 자동 계산됩니다.
- 자동 슬롯의 가중치는 팔레트 색의 채도와 그 색에 대응하는 원본 픽셀의 채도 분포를 비교해 결정합니다. 팔레트 색이 원본보다 강하면 매칭 범위를 좁히고, 약하면 넓혀 원본의 색 배치를 최대한 유지합니다.
- 슬롯 상태 버튼은 `자동`(색·가중치 자동) → `색 고정`(색 고정·가중치 자동) → `고정`(색·가중치 고정) → `자동` 순서로 전환됩니다. 색상 선택기와 프리셋으로 지정한 색은 `색 고정`에서 시작합니다.
- 사용자가 가중치를 직접 입력하면 현재 색상과 가중치를 함께 `고정`하고 이후 변환에서도 입력값을 그대로 사용합니다. 팔레트 전체 초기화는 색상 수를 유지한 채 모든 슬롯을 `#DADAD5` 자리표시자·가중치 `1.0`의 자동 상태로 되돌립니다.
- 최종 픽셀 매핑은 OKLab 거리 제곱을 슬롯 가중치로 나눈 값이 가장 작은 색상을 선택합니다. 가중치 1은 편향이 없고, 값이 클수록 해당 색상의 매칭 범위가 넓어집니다.
- **면 정리 강도**는 `0`(디테일 유지)부터 `100`(깔끔한 면)까지 조절하며 기본값은 `50`(균형)입니다. 먼저 기존 OKLab 최근접 매핑을 수행한 뒤, 원본 색 차이가 작은 평탄한 이웃만 참고해 고립된 팔레트 잡색을 정리합니다. `70` 이후에는 효과가 점진적으로 강해지고 최대값에서는 대각선 이웃과 최대 9단계의 정리를 사용해 비교적 넓은 색 덩어리도 적극적으로 통합합니다. 원본의 강한 경계에서는 정리를 억제하며, 팔레트 밖 색이나 블러를 만들지 않습니다. 값 `0`은 기존 최근접 변환과 완전히 같습니다.
- 디더링은 지원하지 않으며 항상 비활성화됩니다.

## 설정 파일

버전 1 JSON이며 저장 창에서 `ADJUST`(밝기·대비·채도·색조·픽셀화)와 `PALETTE`(최종 색상 수·슬롯 상태·색상·가중치·자동/수동 가중치 상태·자동 팔레트 성향·면 정리 강도)를 각각 선택할 수 있습니다. PALETTE에 실제 색상 값이 있는 슬롯은 저장 및 불러오기 시 고정 색상으로 취급되어 다시 변환해도 자동 생성되지 않습니다. 아직 색상이 계산되지 않은 빈 슬롯만 자동 상태로 유지됩니다. 내보내기 설정과 디더링 비활성 상태는 항상 함께 저장되며 이미지 파일 자체는 포함하지 않습니다. 선택하지 않은 영역은 불러올 때 현재 이미지의 값을 유지합니다. 범위 정보가 없는 기존 버전 1 파일은 전체 설정으로 적용됩니다. 버전·저장 범위·슬롯 수·색상·가중치·필수 값이 잘못되면 사용자에게 오류를 표시합니다.

## 테스트

```bash
pnpm test
```

인위적인 소형 RGBA 이미지를 사용해 색상 수 상한, 고정 색상 보존, 전체 고정 팔레트, 가중치 효과, 투명 픽셀 제외, 설정 왕복, 결정론, 이미지별 상태 분리 및 잘못된 설정 처리를 검증합니다.

## 현재 제한 사항

- 최종 팔레트에는 설정한 수만큼 슬롯이 항상 존재하지만, 원본에 구분 가능한 색이 적거나 특정 가중치가 매우 큰 경우 실제 결과 픽셀에서 일부 슬롯이 사용되지 않을 수 있습니다. 슬롯 사용을 위해 임의의 픽셀을 칠하지는 않습니다.
- 화면 전체 스포이드는 브라우저의 EyeDropper API가 있을 때만 사용할 수 있습니다. 내부 이미지 스포이드는 항상 제공됩니다.
- 전체 내보내기는 여러 파일을 순서대로 다운로드하므로 브라우저가 다중 다운로드 허용을 요청할 수 있습니다.
- JPEG는 알파 채널을 지원하지 않아 선택한 배경색으로 합성합니다. WebP 알파 지원은 브라우저 인코더 지원 범위를 따릅니다.
- 영상 변환은 WebCodecs를 사용할 수 있는 최신 Chrome·Edge를 우선 지원합니다. 장치와 운영체제에 인코더가 없거나 원본 오디오 코덱을 출력 컨테이너에 그대로 담을 수 없으면 변환을 시작하지 않고 오류를 표시합니다.
- 긴 영상과 4K 영상은 처리 시간이 길고 사용자 장치의 CPU/GPU·메모리를 많이 사용할 수 있습니다. 결과 파일은 현재 브라우저 메모리에서 완성되므로 한 번에 영상 하나만 처리합니다.
